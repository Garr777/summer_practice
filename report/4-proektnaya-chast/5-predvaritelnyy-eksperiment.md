Раздел содержит результаты предварительного эксперимента, выполненного на
имеющемся заделе. Его цель — не получить окончательные значения, а проверить
**работоспособность связки** «прогнозная модель → имитационная модель» и
обоснованность приёмочного барьера, введённого в
[разделе 4.4.3](4-metodologiya-soprovozhdeniya.md).

## 4.5.1. Условия эксперимента

Данные — выборка, описанная в
[разделе 2.1.6](../2-problematika/1-protivorechie.md): свыше 420 тысяч
прогонов промышленного конвейера за 47 суток. Разделение на обучающую и
контрольную части выполнено **по времени** в отношении 70/30: около 295 тысяч
прогонов на обучение, около 126 тысяч — на контроль.

Сопоставляются три политики назначения запросов:

| Политика | Содержание |
|---|---|
| `configured` | запросы, фактически заданные инженерами, — действующая база сравнения |
| `heuristic` | перцентиль потребления задачи с коэффициентом запаса, округлением и границами |
| `model` | квантильная регрессия на градиентном бустинге по признакам, известным до запуска |

Квантили заданы раздельно по ресурсам: 0,95 для памяти, 0,90 для процессора
([раздел 2.3.4](../2-problematika/3-karta-probelov.md)).

## 4.5.2. Качество прогноза

Показатель **покрытия** — доля прогонов контрольной выборки, чьё устойчивое
потребление не превысило назначенный запрос. Показатель **резерва** — средняя
доля незадействованной части запроса.

**Память** (целевой квантиль 0,95):

| Политика | Покрытие | Непроизводительный резерв | Средний запрос |
|---|---|---|---|
| `configured` | 68,3 % | 24,3 % | 3 185 Ми |
| `heuristic` | **97,2 %** | 54,7 % | 7 996 Ми |
| `model` | 93,4 % | **47,3 %** | 7 030 Ми |

**Процессор** (целевой квантиль 0,90):

| Политика | Покрытие | Непроизводительный резерв | Средний запрос |
|---|---|---|---|
| `configured` | 51,9 % | 16,0 % | 943 м |
| `heuristic` | **97,0 %** | 52,4 % | 3 498 м |
| `model` | 88,8 % | **42,2 %** | 2 949 м |

Из таблиц следуют три наблюдения.

**Действующая конфигурация покрывает распределение существенно ниже
безопасного уровня.** Покрытие 68,3 % по памяти означает, что почти треть
прогонов выходит за назначенный запрос, — это согласуется с измерением
базовой линии и подтверждает существование проблемы.

**Обучаемая модель не превосходит эвристику по обоим показателям
одновременно.** Она уступает по покрытию (93,4 % против 97,2 %) и выигрывает по
резерву (47,3 % против 54,7 %), то есть занимает иную точку на кривой
компромисса, а не доминирует. Сопоставление квантилей показывает причину:
эвристика систематически **перевыполняет** целевой уровень (97,2 % при цели
95 %) из-за коэффициента запаса, наложенного поверх перцентиля, тогда как
модель приближается к нему снизу (93,4 %).

**Выбор между политиками по этим таблицам невозможен.** Эвристика безусловно
лучше по критерию надёжности, модель — по критерию экономии, а действующая
конфигурация радикально дешевле обеих. Метрики прогноза не содержат
информации, позволяющей предпочесть одну другой.

## 4.5.3. Системное последствие

Тот же поток задач воспроизведён на имитационной модели пула при
конфигурации, соответствующей эксплуатируемой: 16 узлов, предел параллелизма
240. Сравниваются политики `configured` и `heuristic`; подключение политики
`model` к имитационной модели составляет содержание
[задачи 5](2-zadachi-vkr.md) и на момент подготовки отчёта не выполнено.

| Показатель | `configured` | `heuristic` |
|---|---|---|
| Средний запрос памяти | 3 254 Ми | 6 495 Ми |
| Помещается на пул одновременно | 282 задачи | **141 задача** |
| Время ожидания, медиана | **0 с** | **50 мин** |
| Время ожидания, p90 | 0 с | **4 ч 04 мин** |
| Время ожидания, p99 | 0 с | **7 ч 11 мин** |
| Время ожидания, максимум | 16 мин | 8 ч 58 мин |
| Пиковый параллелизм | 152 из 240 | 117 из 240 |
| Утилизация памяти, пик / среднее | 88,5 % / 23,5 % | 98,1 % / 45,1 % |
| Недооценка по памяти | 34,2 % | **3,0 %** |

Результат однозначен. Эвристика снижает недооценку по памяти с 34,2 % до
3,0 % — более чем в одиннадцать раз, — и это именно то улучшение, которое
предсказывают метрики прогноза. Одновременно она **делает конвейер
непригодным к эксплуатации**: медианное время ожидания задачи вырастает с нуля
до пятидесяти минут, а девять прогонов из десяти ждут дольше четырёх часов.

Причина видна из первых двух строк таблицы. Удвоение среднего запроса вдвое
сокращает число задач, помещающихся на пул: 141 против 282 при пределе
параллелизма 240. Предел параллелизма перестаёт быть действующим
ограничением — им становится ёмкость по памяти, и очередь растёт неограниченно.

Существенно, что этот эффект **невозможно обнаружить** ни по одной из метрик
раздела 4.5.2: они вычисляются по отдельным прогонам и не содержат
сведений ни о ёмкости пула, ни о степени параллелизма, ни о взаимном
вытеснении задач.

## 4.5.4. Выводы эксперимента

**1. Пробел П2 подтверждён экспериментально.** Утверждение о том, что
улучшение метрик прогноза не гарантирует улучшения поведения системы, до сих
пор выдвигалось как гипотеза на основании анализа литературы
([раздел 2.3.2](../2-problematika/3-karta-probelov.md)). Эксперимент даёт
прямое подтверждение: политика, безусловно превосходящая базу сравнения по
метрике надёжности, ухудшает время обратной связи конвейера на два порядка.

**2. Приёмочный барьер на имитационной модели необходим и достаточен для
данного случая.** Правило, сформулированное в
[разделе 4.4.3](4-metodologiya-soprovozhdeniya.md), отклонило бы политику
`heuristic` по условию о времени ожидания — до её применения к промышленному
контуру и без каких-либо отказов в эксплуатации. Это и есть та функция, ради
которой имитационная модель вводится в контур сопровождения в качестве
отдельной стадии, а не вспомогательного инструмента.

**3. Гипотеза исследования уточняется.** В формулировке
[раздела 4.1.4](1-tema-i-apparat.md) предполагалось одновременное улучшение
двух показателей — надёжности и экономии. Эксперимент показывает, что
постановка задачи как двухкритериальной оптимизации неполна: **третьим
критерием выступает достижимая степень параллелизма**, и он способен
обесценить выигрыш по первым двум. Уточнённая формулировка звучит так: искомая
конфигурация должна улучшать покрытие распределения при непревышении заданной
границы времени ожидания в заданных режимах нагрузки.

**4. Направление доработки прогнозной модели определено.** Модель
недовыполняет целевой квантиль (93,4 % при цели 95 %), а её средний запрос
близок к эвристическому. Следовательно, первоочередная задача — не повышение
точности как таковой, а **калибровка**: предсказанный квантиль должен
соответствовать заданному, поскольку именно он является управляющим
параметром риска. Это уточняет содержание
[задачи 4](2-zadachi-vkr.md).

**5. Обоснована практическая осуществимость метода.** Полный цикл — подготовка
выборки, обучение двух моделей, воспроизведение потока из 392 тысяч задач на
имитационной модели — выполняется за время порядка минуты на обычном
процессоре. Это позволяет включить приёмочную проверку в автоматизированный
контур ([раздел 4.4](4-metodologiya-soprovozhdeniya.md)), а не выполнять её как
разовое исследование.
